% Executive Summary
\section{Executive Summary}

This report presents a comprehensive security analysis of a simulated SCADA (Supervisory Control and Data Acquisition) environment developed as part of the CS437 Cybersecurity Practices \& Applications course at Sabancı University. The project demonstrates critical vulnerabilities commonly found in industrial control systems and web applications, along with their secure implementations and monitoring mechanisms.

\subsection{Project Scope}

The project implements:
\begin{itemize}[leftmargin=*]
    \item \textbf{9 Critical Vulnerabilities:} Authentication Bypass, Privilege Escalation, SQL Injection, IDOR \& Unsafe Temp Files, XXE, Deserialization RCE, File Upload \& Overwrite, SSRF, and Security Misconfiguration
    \item \textbf{Dual Implementations:} Each vulnerability has both vulnerable and patched versions
    \item \textbf{Patched Implementations:} Secure versions demonstrating proper mitigation techniques
    \item \textbf{Real-time Monitoring:} Middleware-based attack detection and logging system
    \item \textbf{Containerized Environment:} Docker-based deployment for reproducibility
\end{itemize}

\subsection{Key Findings}

Our analysis revealed that all implemented vulnerabilities are exploitable in the vulnerable version, successfully blocked in the patched version, and correctly detected by the monitoring system. The database contains 21 devices, 100+ maintenance logs, and admin-only diagnostic reports for testing.

\subsection{Technologies Used}

\begin{itemize}[leftmargin=*]
    \item \textbf{Backend Framework:} Django 6.0 on Python 3.12
    \item \textbf{Database:} SQLite3 with custom population script
    \item \textbf{Containerization:} Docker Compose with volume mapping
    \item \textbf{Security Libraries:} lxml (XXE), pickle (deserialization), ReportLab (PDF generation)
\end{itemize}

\subsection{Vulnerability 1: Authentication Bypass - CVE-2025-64459 (CWE-287)}

\subsubsection{Description}
Critical authentication bypass vulnerability exploiting Django ORM's Q() object \texttt{\_connector} parameter manipulation (CVE-2025-64459). This vulnerability affects Django versions 4.2 < 4.2.26, 5.1 < 5.1.14, and 5.2 < 5.2.8.

The vulnerability allows attackers to bypass authentication by injecting a \texttt{connector=OR} parameter that manipulates the SQL WHERE clause logic, combined with arbitrary field parameters like \texttt{is\_superuser=True}. This transforms authentication checks from AND logic to OR logic, allowing unauthorized access.

\textbf{CVSSv3.1 Score: 9.1 (Critical)}

\textbf{Attack Vector:} The application constructs Q() objects using dictionary expansion from GET parameters, allowing attackers to inject the special \texttt{\_connector} field that controls SQL logic operators.

\subsubsection{Vulnerable Code (vulnerable/views.py, Lines 45-92)}

\begin{lstlisting}[language=Python]
@csrf_exempt
def vulnerable_login(request):
    # GET: CVE-2025-64459 SQL Injection via connector parameter
    if request.method == "GET":
        if 'username' in request.GET and 'connector' in request.GET:
            username = request.GET.get('username')
            connector = request.GET.get('connector', 'AND').upper()
            
            # Start with basic username query
            query = Q(username=username)
            
            # CRITICAL VULNERABILITY: Q() object connector manipulation
            # Attacker controls the SQL logic operator (AND vs OR)
            for key, value in request.GET.items():
                if key in ['username', 'connector']:
                    continue
                    
                # CVE-2025-64459: Connector parameter injection
                if connector == 'OR':
                    # Transforms: WHERE username='X' AND is_superuser=True
                    # Into: WHERE username='X' OR is_superuser=True
                    query |= Q(**{key: value})  # OR logic - DANGEROUS!
                elif connector == 'AND':
                    query &= Q(**{key: value})  # AND logic
            
            # Execute query with injected logic
            user = User.objects.filter(query).first()
            
            if user:
                # AUTHENTICATION BYPASS: Login without password check!
                login(request, user)
                request.session['user'] = {
                    'username': user.username,
                    'is_admin': user.is_superuser
                }
                return redirect('vulnerable_dashboard')
\end{lstlisting}

\subsubsection{Exploitation}

\textbf{Attack: CVE-2025-64459 Q() Connector Manipulation}
\begin{lstlisting}[language=bash]
# Navigate to this URL in browser:
http://localhost:8000/vulnerable/login/?username=hacker&connector=OR&is_superuser=True

# Attack mechanism:
# 1. Server constructs: Q(username='hacker')
# 2. Server detects connector=OR parameter
# 3. Server adds: query |= Q(is_superuser=True)
# 4. Final SQL: WHERE username='hacker' OR is_superuser=True
# 5. Since is_superuser=True, OR condition bypasses username check
# 6. Any user with is_superuser=True in database is returned (admin)
# 7. Login succeeds WITHOUT password verification
# 8. Session established with admin privileges
\end{lstlisting}

\subsubsection{Monitoring Detection (monitoring/middleware.py, Lines 60-86)}

The SecurityMonitorMiddleware detects CVE-2025-64459 exploitation with \textbf{PRIORITY 1} detection (checked before Brute Force):

\begin{lstlisting}[language=Python]
# VULNERABILITY DETECTION #1: CVE-2025-64459 Authentication Bypass
# Endpoint: /login/ - PRIORITY CHECK (before Brute Force)
if '/login/' in endpoint:
    # Pattern 1: Connector parameter (CVE-2025-64459)
    if re.search(r"(?i)(connector=)", search_space):

        severity = 'CRITICAL'

            'IMMEDIATE: Block IP and revoke all sessions. '
            'This is CVE-2025-64459 exploitation allowing authentication bypass.'
        )
\end{lstlisting}

\textbf{Detection Mechanism:}
\begin{itemize}[leftmargin=*]
    \item \textbf{Search Space:} Full URL path + POST body content
    \item \textbf{Pattern Matching:} Regex search for \texttt{connector=} parameter (case-insensitive)
    \item \textbf{Priority:} Checked BEFORE brute force detection (Line 60 vs Line 88)
    \item \textbf{Severity:} Always \texttt{CRITICAL} due to complete authentication bypass
    \item \textbf{Auto-Blocking:} Triggers automatic IP block if \texttt{ENABLE\_AUTO\_BLOCKING=True}
\end{itemize}

\subsubsection{Patch Implementation (patched/views.py, Lines 15-41)}

\begin{lstlisting}[language=Python]
def patched_login(request):
    # FIX 1: Logout on GET request (no GET parameter processing)
    if request.method == "GET":
        request.session.flush()
        return render(request, 'patched/login.html')
    
    # FIX 2: POST-only authentication
    if request.method == "POST":
        username = request.POST.get('username')
        password = request.POST.get('password')
        
        # FIX 3: Django's built-in authenticate() with password verification
        user = authenticate(request, username=username, password=password)
        
        if user is not None:
            login(request, user)
            # FIX 4: Server-side session construction (no user input)
            request.session['user'] = {
                'username': user.username,
                'is_admin': user.is_superuser  # From database only!
            }
            return redirect('patched_dashboard')
\end{lstlisting}

\textbf{Key Mitigations:}
\begin{enumerate}[leftmargin=*]
    \item \textbf{GET Request Handling:} GET requests flush session - NO parameter processing
    \item \textbf{POST-Only Authentication:} Credentials only accepted via POST body
    \item \textbf{No Q() Object Construction:} No dynamic query building from user input
    \item \textbf{Built-in authenticate():} Uses Django's password verification backend
    \item \textbf{Server-Side Authorization:} \texttt{is\_admin} flag set from database field only
\end{enumerate}

The application accepts base64-encoded pickled diagnostic objects and deserializes them without validation. Python's pickle module can execute arbitrary code during deserialization, enabling Remote Code Execution (RCE) attacks.

def vulnerable_deserialize(request):

    output = ""

    if request.method == 'POST':
        payload = request.POST.get('payload')
        if payload:
            try:

\subsection{Vulnerability 4: File Overwrite (CWE-434)}

\subsubsection{Description}
Uploaded diagnostic files overwrite existing files with the same name without warning. The application uses \texttt{FileSystemStorage} without uniqueness checks.

\subsubsection{Vulnerable Code (vulnerable/views.py, Lines 197-225)}

\begin{lstlisting}[language=Python]
@csrf_exempt
def vulnerable_upload(request):
    context = {'status': 'Waiting for upload...'}
    
    if request.method == 'POST' and request.FILES.get('file'):
        uploaded_file = request.FILES['file']
        
        # VULNERABILITY: No filename uniqueness check
        fs = FileSystemStorage(location='media/uploads/')
        
        # DANGEROUS: Uses original filename directly
        filename = fs.save(uploaded_file.name, uploaded_file)
        file_path = fs.path(filename)
        
        context['status'] = f"Uploaded: {filename}"
\end{lstlisting}

\subsubsection{Exploitation}

\begin{lstlisting}[language=bash]

\section{Monitoring System}

\subsection{Architecture Overview}

The monitoring system is implemented as Django middleware (\texttt{SecurityMonitorMiddleware}) that intercepts all HTTP requests before they reach application views. This defense-in-depth approach ensures attack detection occurs even when vulnerabilities are patched. The system operates in three layers:

\begin{itemize}[leftmargin=*]
    \item \textbf{Request Interception Layer:} Middleware examines all incoming HTTP requests
    \item \textbf{Pattern Detection Layer:} Regex-based attack pattern matching with endpoint-specific rules
    \item \textbf{Action Layer:} Automated logging, severity classification, and optional IP blocking
\end{itemize}

\subsection{Core Components}

\subsubsection{Database Models}

Three Django models support the monitoring infrastructure:

\begin{lstlisting}[language=Python]

    reverse_action = models.TextField()

    blocked_by = models.CharField(max_length=100)  # Admin username

\subsubsection{Middleware Initialization}

\subsection{Detection Functionalities}

\subsubsection{1. IP Blocking Check (First Defense Layer)}

Before processing any request, the middleware verifies if the source IP is blocked:

\begin{lstlisting}[language=Python]
def __call__(self, request):
    client_ip = request.META.get('HTTP_X_FORWARDED_FOR', '').split(',')[0].strip()
    if not client_ip:
        client_ip = request.META.get('REMOTE_ADDR', '')
    
    # IMMEDIATE BLOCK: Check if IP is in blocked list
    if client_ip in self.blocked_ips:
        return HttpResponse(
            "403 Forbidden - Your IP address has been blocked due to suspicious activity.",
            status=403
        )
\end{lstlisting}

\textbf{Purpose:} Prevents known attackers from consuming server resources. This check occurs before any other processing, ensuring blocked IPs cannot interact with the application.

\subsubsection{2. Request Context Extraction}

The middleware extracts comprehensive request details for pattern matching:

\begin{lstlisting}[language=Python]
    # Extract all request components
    full_path = request.get_full_path()  # URL with query parameters
    endpoint = request.path              # URL path only
    method = request.method              # GET/POST/PUT/DELETE
    body_content = request.body.decode('utf-8', errors='ignore')[:1000]
    
    # Combine for comprehensive search space
    search_space = f"{full_path} {body_content}"
\end{lstlisting}

\textbf{Rationale:} Attacks may appear in URLs (SQL injection), request bodies (XXE), or both. Comprehensive extraction ensures no attack vector is missed.

\subsubsection{3. Brute Force Detection}

Tracks failed login attempts with time-based thresholds:

\begin{lstlisting}[language=Python]
def check_brute_force(self, request, ip):
    """Detects brute force attacks: 7+ = HIGH, 10+ = CRITICAL"""
    if '/login/' in request.path and request.method in ['GET', 'POST']:
        # Log this attempt
        FailedLoginAttempt.objects.create(
            ip_address=ip,
            username=request.GET.get('username') or request.POST.get('username', ''),
            endpoint=request.path
        )
        
        # Count recent attempts from same IP
        one_min_ago = timezone.now() - timedelta(minutes=1)
        recent_attempts = FailedLoginAttempt.objects.filter(
            ip_address=ip,
            timestamp__gte=one_min_ago
        ).count()
        
        # Apply thresholds
        if recent_attempts >= 10:
            severity = 'CRITICAL'
            attack_type = f'Brute Force Attack - CRITICAL ({recent_attempts} attempts/min)'
            recommended_action = 'IMMEDIATE: Block IP, review all login logs, check for credential stuffing'
        elif recent_attempts >= 7:
            severity = 'HIGH'
            attack_type = f'Brute Force Attack - HIGH ({recent_attempts} attempts/min)'
            recommended_action = 'Monitor IP closely, block if attempts continue'
        else:
            return  # Below threshold, no alert
        
        # Create attack log
        AttackLog.objects.create(
            ip_address=ip,
            endpoint=request.path,

\subsubsection{10. Cookie Manipulation Detection}

Validates session cookie integrity across all requests:

\begin{lstlisting}[language=Python]
def detect_cookie_manipulation(self, request):
    """Validates Django session cookie format and integrity"""
    session_id = request.COOKIES.get('sessionid', '')
    if not session_id:
        return False
    
    # Django sessionid characteristics:
    # - Length: 32 characters
    # - Format: Alphanumeric hex string
    # - Generated by: secrets.token_hex(16)
    
    suspicious_patterns = [
        len(session_id) != 32,           # Wrong length
        not session_id.isalnum(),        # Contains special chars
        session_id in ['admin', 'root', '12345', '00000000000000000000000000000000']
    ]
    
    if any(suspicious_patterns):
        AttackLog.objects.create(
            ip_address=get_client_ip(request),
            endpoint=request.path,
            attack_type='Cookie Manipulation Attack',
            payload=f'Invalid sessionid: {session_id[:20]}...',
            severity='HIGH',
            recommended_action='Revoke session, force re-authentication, monitor IP'
        )
        return True
    
    return False
\end{lstlisting}

\textbf{Validation Checks:}
\begin{itemize}[leftmargin=*]
    \item \textbf{Length:} Django uses 32-character hex strings
    \item \textbf{Format:} Must be alphanumeric (0-9, a-f)
    \item \textbf{Common Attacks:} Detects predictable values (admin, root, 12345)
\end{itemize}

def revoke_session_action(request, log_id):
    """Revoke user session for suspicious activity (Admin only)"""
    user = request.session.get('user', {})
    if not user.get('is_admin'):
        return JsonResponse({'status': 'error', 'message': 'Unauthorized'}, status=403)
    
    log = get_object_or_404(AttackLog, id=log_id)
    
    # Check if admin is revoking their own session
    current_ip = request.META.get('HTTP_X_FORWARDED_FOR', '').split(',')[0].strip()
    if not current_ip:
        current_ip = request.META.get('REMOTE_ADDR', '')
    
    if current_ip == log.ip_address:
        # Revoke current session
        request.session.flush()
        redirect_url = '/patched/login/' if 'patched' in log.endpoint else '/vulnerable/login/'
        message = 'Your session has been revoked. Redirecting to login...'
        should_redirect = True
    else:
        # Mark session as revoked (in production, delete from session store)
        redirect_url = None
        message = f'Session marked as revoked for IP {log.ip_address}'
        should_redirect = False
    
    # Update log
    log.action_taken = 'SESSION_REVOKED'
    log.save()
    
    response = {'status': 'success', 'message': message}
    if should_redirect:
        response['redirect'] = redirect_url
    
    return JsonResponse(response)
\end{lstlisting}

\textbf{Smart Behavior:}

    \item If revoking another user: Log marked, no self-logout

\subsection{False Positive Prevention}

To minimize false alarms:

\begin{itemize}[leftmargin=*]
    \item \textbf{Endpoint-Specific Detection:} XXE only checked on \texttt{/upload/}, SSRF only on \texttt{/ssrf/}
    \item \textbf{Content-Based Analysis:} Checks both URL and request body for comprehensive coverage
    \item \textbf{Threshold-Based Alerts:} Brute force requires 7+ attempts, directory scanning 20+ 404s
    \item \textbf{Whitelist Approach:} PDF uploads don't trigger alerts, only executable extensions
    \item \textbf{Case-Insensitive Regex:} Catches evasion attempts (IS\_ADMIN=TRUE, Is\_Admin=1)
    \item \textbf{Separate Logging:} Vulnerable and patched versions logged independently
\end{itemize}

% Security Best Practices
\section{Security Best Practices}

\subsection{Lessons Learned}

\subsubsection{Input Validation}
\begin{itemize}[leftmargin=*]
    \item Always use whitelist approach over blacklist
    \item Validate data type, length, format, and range
    \item Never trust client-side validation alone
\end{itemize}

\subsubsection{Authentication \& Authorization}
\begin{itemize}[leftmargin=*]
    \item Explicitly set authorization flags server-side
    \item Implement role-based access control (RBAC)
    \item Verify resource ownership before granting access
    \item Use POST for state-changing operations
\end{itemize}

\subsubsection{Safe Deserialization}
\begin{itemize}[leftmargin=*]
    \item Prefer JSON, Protocol Buffers over pickle
    \item Validate object types after deserialization
    \item Implement integrity checks (HMAC signatures)
\end{itemize}

\subsubsection{File Operations}
\begin{itemize}[leftmargin=*]
    \item Use UUID-based filenames to prevent collisions
    \item Generate unique temp files per request
    \item Clean up temporary files after use
    \item Whitelist allowed file extensions and MIME types
\end{itemize}

\subsection{Recommended Security Headers}

\begin{lstlisting}[language=Python]
# settings.py
SECURE_BROWSER_XSS_FILTER = True

X_FRAME_OPTIONS = 'DENY'

SESSION_COOKIE_HTTPONLY = True
\end{lstlisting}

Regular updates required for:
